# ADR-0112: A call's arguments are matched to each candidate's parameters before it is tried, as cjc

Status: proposed

## Context

- D63 tries each candidate of a call, but chose which to try by the count of the arguments alone (`Callable.takes`), and each try laid the arguments out again by itself: a named one inferred alone, a variadic one's elements checked in `quiet`. What could not be told was `TodoTy(ArgMatching)` (D77): 333 expressions on this repository, 149 roots (#254). Two calls were typed wrong, not left a gap: `w(1, c: 2)` of `w(a, b!)` and `w(a, c!)` took the first (`overriding` kept one of two of the same types whatever their names), and an untyped lambda was one argument of a constructor like any other (`Lazy { … }` took `init(value: T)`).
- cjc (R3, `TypeCheckCall.cpp`) matches before it checks a type: `CheckCandidate` → `CheckArgsWithParamName` → `GetParamTysInArgsOrder` give each argument its parameter, or fail the candidate. As many in order as the parameters passed in order, a parameter passed by name only by name, no name unknown or twice, each parameter left out of a default value. A variadic call is a second pass (`ChkVariadicCallExpr`), only if the first found none at any level: the last parameter passed in order an `Array`, of no enum constructor, the tail packed into an array literal, the candidates grouped by how many parameters come before it, the call ambiguous if several groups give one. `SyntaxFilterCandidates` ranks the candidates by where the lambdas go first. `CompareFuncCandidates` compares the parameters of the arguments passed, in their order (`tysInArgOrder`); a default value left out gives no priority. A value of a function type takes no name. The chosen one's arguments are checked again against its parameters solved (`ReInferCallArgs`).
- K2 (R7, R9) maps arguments as a stage of each candidate too, but prefers one using no default and no vararg; cjc does not (`d(1)` of `d(a, b! = 0)` and `d(a)` is ambiguous). R1 has no names.
- cjc 1.3.0-alpha.20261002 (N154–N158, in #254's PR): `u(1)` of `u(Int64, Array<Int64>)` and `u(Int64)` takes the second, `e(1, 2, 3)` the one of three; `v(1, arr)` passes the array as it is; `h(n: 3)` of `h(xs: Array<Int64>, n!: Int64 = 1)` packs none; `k(1) { x => x }` of `k(a, h!: (Int64) -> Int64)` passes the lambda by `h`; `Array<Int64>(3) { i => i }` never tries `init(size, repeat!: T)`.

## Decision

- **Matched first, as cjc** (option A of #254): `matchArgs` gives each argument the place of its parameter (`ArgMatch`), or why the candidate does not match (`ArgFailure`), before a type is looked at; `callWith`, a generic call's solver and `isMoreSpecific` read the parameters through it. A desugaring at the call as cjc's (C: the tail an array literal of the HIR) was the other; the HIR knows no candidates, and a literal made per candidate would be expressions no source wrote (A29).
- **Variadic as cjc's second pass** (option A): only if no candidate matched as the arguments are, at any level; grouped by fixed arity. One pass with the variadic ones a level under the others (B) differs from cjc where a nearer variadic one meets a farther exact one.
- **Kept** (option A): `InferenceResult.paramsOf(callee)`, the parameter each argument of the call taken goes to, for inlay hints of parameter names (#204) and signature help; B kept it inside inference.
- **Reported, for one function** (option A): the argument's name unknown or given twice, none where one is wanted (listing the names left), a name to a value of a function type, the count; chosen as cjc's `FilterIncompatibleCandidatesForCall` does: a name if the count may be right, else the count; of a variadic one, what its first try found. Of several, nothing yet (cjc's "no matching function").
- **Lambdas rank the candidates first**, as `SyntaxFilterCandidates`: a trailing lambda only to a last parameter of a function type, then those whose lambdas go to a function type, `Any` or a type parameter. **A lambda is checked again** against its parameter solved, its body boxed into the `Option` that parameter returns.
- On the way, what the matching needed: a trailing lambda is marked in the HIR (`CallArg.isTrailing`) and passed by the last parameter's name if it has one; a local function's parameters carry the name they are passed by (`BodyParam.passedBy`); a `.cjo` parameter has a default value if `HasInitial`, cjc writing the value itself only for a constant (`ASTWriter::SaveParamDecl`); two overloads of the same types but other names are two, not an override.

## Consequences

- On this repository, master `4f9021a` against this change (1 080 expressions more, its tests): expressions of no type known 4 585 → 4 176, `ErrorTy` 629 → 552, `TodoTy(ArgMatching)` 333 → none, the case gone; `TodoTy(MacroMember)` 3 362 → 3 363. `error_roots_known.txt` loses 40 roots (the fuzz tests' `Array(n, repeat:)`, `lsp_codegen`'s config test, stdxx's derive helpers). The gate of std's sources keeps its list; this repository has no diagnostic.
- Not yet: a name given to a parameter passed in order is told as unknown, not as cjc's "target is not a named parameter": a signature knows the names of those passed by name only (#204 needs the others too); an argument after one by name is the parser's to report; of several candidates none of which fits, nothing is reported.
