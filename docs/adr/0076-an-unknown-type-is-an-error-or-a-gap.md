# ADR-0076: A type not known is an error the user made or one the analysis cannot find, and why; a type or package before a dot is no value

Status: proposed

## Context

- Inference (D55) gives `ErrorTy` to whatever it cannot type, and finds mismatches (8d) only to compare candidates (D63); nothing it finds is reported (#53, #48 step 8c′). On this repository at `b14ebada`, 13 131 of 181 426 expressions were of `ErrorTy`, for three reasons at once: the user erred (none here: cjc accepts it all), the analysis cannot (a macro call 2 850, a member a macro declares, a call by name), and no value at all (a type or package before a `.`, 3 796). Reported as it was, a file cjc accepts would turn red.
- Prior art (`docs/prior-art.md` § Semantic diagnostics): R1 has one `Error`, fitting anything, and drops a diagnostic about a value of a type holding it (`resolve_diagnostics`); R2 (ty) has two dynamic types, `Unknown` (an error, reported) and `Todo` (a limitation of ty, its reason shown in debug builds only); R6 checks `ContainsErrorType` at any depth; R3 asserts an invalid type never reaches a mismatch. R1 lowers `Type::member` into one path, the type no expression.
- cjc 1.3.0-alpha.20261002 (N136–N139, in step 8c′a's PR): `quote(…)` is a `std.ast.Tokens` where the file imports anything of `std.ast`; `@Expect`, `@Assert`, `@PowerAssert`, `@FailExpect` are `Unit`, `@Fail` `Nothing`, `@AssertThrows[E]` an `E`, of `[A | B]` their join, of none an `Exception`, `@ExpectThrows[E]` an `Option<E>`, of `[A | B]` or none an `Option<Exception>`; under `--test` (`cjpm test`) std.unittest.testmacro's macros need no import. An `if`, `match` or `try` whose value is not used needs no join of its branches. A static member called on a type parameter is seen on its bound (`T.make()` of `T <: Make<T>` a `T`).

## Decision

- **Two kinds of a type not known**, as R2's: `ErrorTy`, only where cjc reports an error as far as the analysis follows cjc; `TodoTy(why)`, where the analysis cannot find a type cjc may well find, `why` one of `Todo`'s cases (a macro call, a member or name a macro may declare, an argument matched by name, default or variadic, a `.cjo`'s type not read, no std, a local function's type parameter). Both fit any type (`isSubtype`), so neither cascades; both are `{unknown}` to a hover. What is made of one is that one (`unknownOf`), a `TodoTy` before an `ErrorTy`: a failure with a gap among its inputs may be no failure once the gap is closed. A failure of known types alone is an `ErrorTy`, unless a macro whose expansion is not read is called on the type or in the package it looks in (#176).
- **The reason is in the `Ty`**, an interned enum of a handful of cases, not a debug string as R2's: it is read by the census test of a release build and by the diagnostics to come (8c′b) to stay silent, and it costs one interned `Ty` per case. Two types differing in reason alone are two types; nothing compares them but equality of signatures, where both stand for any.
- **A type or package before a `.` is no value**: `InferenceResult.exprs` holds `None` for it (`result[expr]` was `?Ty` already), not a type of either kind. R1's lowering into one path needs to know, while lowering, that the name is a type: a local may shadow it (`let E = …; E.A`), and scopes are computed from the lowered body (D50), so it would be a cycle. A mark beside the type in `InferenceResult` would still need a type for the expression, which it has not.
- **`quote` and std.unittest's expression macros are typed by a table** (N136), keyed by the declaration the call resolves to in std.unittest.testmacro (a user's `@Expect` is a `TodoTy`); `Exception` and std.ast's `Tokens` are lang items (A28). A macro of a `[…]` and one of none, declared under one name (`@Expect`, `@AssertThrows`), is one macro.

## Consequences

- On this repository (`CJLS_CENSUS=1` `InferenceCensusTest`), master `b14ebada`'s 13 131 expressions of an error type of 181 426 are, of 183 018 after: 3 869 no value (the qualifiers); 877 `ErrorTy` and 3 975 `TodoTy` (`MacroMember` 2 561, `ArgMatching` 1 203, `MacroCall` 211); the rest, about 4 400, typed (std.unittest's macro calls and what was made of them, N138, N139, `f(a) {…}`). Of the `ErrorTy`s, 142 are roots other than a local, each a gap of the analysis on a source cjc accepts (`@When`'s twins #149, an `Option` joined with its argument #249, `None<T>`, stdx's `Logger`, a `Range` index, `Byte`'s extensions): 8c′b reports nothing about them, being no mismatch of known types, and its gate names those that would be.
- New gaps, each a `Todo`: #254 (`ArgMatching`), #255 (std.unittest.testmacro's macros under `--test`).
- `f(a) {…}` is one expression, the call with the lambda its last argument, of the whole node: `f(a)` had one of its own that inference never reached.
- A cold pass over every body is about 2% slower (14.10 s → 14.37 s, the medians of seven quiet runs each on filaco.dev).
- 8c′b reports a mismatch only between types holding neither kind, and nothing about a value of either.
