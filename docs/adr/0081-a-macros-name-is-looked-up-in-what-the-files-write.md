# ADR-0081: A macro's name is looked up in what the files write, never in what macros add

Status: proposed

## Context

- #175 decided an expansion is declarations, and a macro std's when its name resolves through the file's imports. Step 2 (`@Derive`) added only `extend`s, which `packageExtends` reads apart from the scope. Step 4's macros declare names a file uses: `@UnittestOption[Int64](zxc)` the struct `KeyZxc` (`config.get(KeyZxc.zxc)`), `@Strategy` a `let` in the place of its function, `@Test func f` the class `TestCase_f`. They belong in `defMap`, and so in `packageExports`.
- With them there, `defMap(p)` reads the expansions of `p`'s files, which resolve their macros' names, which `lookUp` looks up in `defMap(p)`: a cycle of queries on every package with an expanded call. Through imports too: a named import of `q` reads `packageExports(q)`, so `q`'s expansions, so `q`'s imports.
- R1 resolves names and macros in one fixed point per crate (`DefCollector`), crates a DAG. cjls resolves per package in a chain of queries (D44, D46), and D44's fallback for a cycle (A14) would give every query on it its fallback: an import cycle while typing would empty both packages' scopes.
- No macro is ever generated: a `macro` is declared in a `macro package`, compiled before its use; an expansion's `macro` declarations would be no macro cjc could call.

## Decision

- **A package's scope has two stages, `ScopeStage.Written` and `Expanded`**: `defMapAt`, `exportsAt`, `packageImportsAt`, `fileImportsAt` take one; `defMap`, `packageExports`, `packageImports`, `fileImports`, `importsOf` are the `Expanded` stage under their old names, so every other reader is unchanged. A `.cjo` is one package at both.
- **A macro's name is looked up at `Written`**: `lookUp` in `Namespace.Macros`, a qualifier of a macro's path, a macro of a package's exports. Nothing on the way from an item to its expansions reads `Expanded`, so `Expanded` is a function of `Written` and never a cycle (A30).
- **`defMapAt(Expanded)` is the files' items, each file's expansions after it**, an item an expansion replaces left out (`Expansion.replaces`, `@Strategy`'s function). Their redefinitions are found as any.

## Consequences

- Two memos of each stage-keyed query per source package; the `Written` ones are small and change only with the items.
- A cycle of packages through plain imports stays no cycle of queries (D46), with or without macros.
- A macro generated by a macro, which cjc cannot call, is not found either.
