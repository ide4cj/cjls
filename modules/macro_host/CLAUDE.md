# `macro_host` — the macros, built and run

How the workspace's macros are built and run is [D104](../../docs/adr/0104-workspace-macros-are-built-by-cjc-and-run-under-a-deadline.md); std's run from the SDK's libraries is [D123](../../docs/adr/0123-std-macros-run-in-the-macro-server.md); this module is all of it that knows no LSP and no server, so a bench, the diagnostics gate or a CLI over `loupe` can expand them too. The server's thread that drives it, its settings, its `Loop` and the open documents first, is `cjls.macro_host`'s `MacroHost`. Depends on `loupe`, `macro_server`, `project_model` (the host's SDK target), `platform`, `calca` (for `CancelledException`) and `jsonrpc` (for `ErrorLogValue`).

- **The SDK** (`sdk.cj`): `macroSdkIn(home)` is what the macros need of one, its server's paths, its `cjc` (`SdkToolchain`, under `envsetup`'s environment), its version and how it numbers tokens (`tokenNumbersOf`), or why it cannot run them; `MacroSdk.stdLibrary` the library of a package of std's macros it ships.
- **The build** (`build.cj`): `MacroBuilder` builds `loupe.hir.macroBuildPlan`'s packages, as `BuildUnit`s of paths, into one directory with cjpm's arguments, skipping a package whose stamp did not change, under that directory's lock (`cache_lock.cj`, `tryLockCacheDir`, D106), which the server's sweep of old directories takes too. `buildPlan` (`plan.cj`) splits the plan by the directory each macro package's project gives it, the source packages a group links built into it too, and keys what it built by the `Package`, which two projects may name alike (#338). Where a directory is (`dirNameOf` of the cjc version, under the project's cache directory) is the caller's. Tests run a `FakeToolchain`, and one the SDK's `cjc`.
- **A call** (`call.cj`, `answer.cj`): `callDataOf` puts a `MacroRequest` on the wire, recording in a `WireLayout` where each text went, and `outputOf` maps the answer's positions back through it into a `MacroOutput` (D98).
- **The server** (`host.cj`): `GuardedServer` starts `macro_server`'s process for the first call and again after it exits, and kills it once a call runs past its deadline (D87); `MacroServers` two of them, std's calls in one; `sendableRequests` picks the requests whose library is built at the stamp the analysis has, or of std is in the SDK, `expandAll` sends them until the files change under the snapshot. The deadlines are `Deadlines`, a test's fired by hand. `drift_test.cj` holds `loupe`'s own expansions of std's macros (#175) to what the SDK's std declares; `diagnostics_gate_test.cj` is the diagnostics gate over this repository with its macros built and expanded by the SDK (#434).
