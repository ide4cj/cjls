# `macro_server` — macros run in the SDK's `LSPMacroServer`

What the server is and how it is driven is [D87](../../docs/adr/0087-workspace-macros-run-in-the-sdks-macro-server.md); this module is its protocol, nothing of loupe or LSP.

- **`src/format.cj` is generated** by `modules/fbs_codegen` from `MacroMsgFormat.fbs` as `macro_msg_format.toml` says (`write = true`: the views and the `<Name>Data` writers); never edit it. A new nightly: take `schema/MacroMsgFormat.fbs` of the cangjie_compiler commit it was built from, put that commit in the config, regenerate (`cjpm build && target/release/bin/fbs_codegen modules/macro_server/macro_msg_format.toml`), and read `src/Macro/MacroEvaluationSrv.cpp` and `MacroEvalMsgSerializer.cpp` at that commit for what the server does with each field.
- **The wire** (`frame.cj`): a native `size_t` length, 8 bytes little-endian on every target cjls is built for, then a `MacroMsg`.
- **A call** (`MacroConnection.expand`): one `MacroCall` in a `multiCalls`, its `MacroResult` read, then `exitTask(false)` (no answer), so the diagnostics of a call do not reach the next. cjc reads `id`, `begin`, `end`, `methodName`, `packageName`, `libPath` and every vector without a null check: a call sets them all. `methodName` is `macroCall_{a|c}_<Macro>_<package, '.' as '_'>` (`a`: with attributes).
- **The process** (`startMacroServer`): on POSIX through `/bin/sh`, which moves the stdio pipes to fds 3 and 4 (`process.cj`); on Windows by `CreateProcessW` through FFI, inheriting its two pipe handles and stderr alone, suspended until it is in a kill-on-close job ([D91](../../docs/adr/0091-the-windows-macro-server-is-started-by-createprocessw.md), `process_windows.cj`). What Windows is given as text (UTF-16, the quoting, the environment block) is built in `windows_command.cj` and tested on every platform; the rest only CI's Windows runs.
- **Tokens** (`macroTokens`, [D95](../../docs/adr/0095-cjc-token-kinds-are-numbered-by-the-sdks-tokens-inc.md)): cjsyntax's tokens cut as cjc's lexer cuts them, numbered by the SDK's own `include/cangjie/Lex/Tokens.inc` (`TokenNumbers`), never a table of ours. What cjc cuts otherwise than cjsyntax (a string whole, `>=>`, `!in`) is written down on `MacroTokenWriter`, verified through `std.ast.cangjieLex`: where cjc's sources and its lexer disagree, the lexer is right.
- **Text** (`printMacroTokens`): the reverse of `macroTokens`, the server's answer printed as source that `macroTokens` cuts into the same kinds and values, each token's range in it beside the positions the server gave. A literal is printed in the first quoting that lexes back to its value (checked by `macroTokens` itself); a space separates two tokens unless one is known never to glue.
- **Tests** run the SDK's own server (`CANGJIE_HOME`) on std's `@Derive`, whose library ships with the SDK: nothing is built. The tokens are held to `std.ast`, which a test may import and the package never does (no `std.ast` in runtime packages): the numbers to `getTokenKind`, `macroTokens` to `cangjieLex` over this repository and std's sources (`.corpora/cangjie_runtime`).
